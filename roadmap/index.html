This alpha, what changed, and what is next

0.4.0-alpha1 is an alpha that is not yet published: expect interfaces to change before 1.0, and pin the version. Beyond it, the upstream roadmap is a plan, and the proposals are proposals.

wireframe 0.4.0-alpha1 · samples verified 2026-11-19

Not yet published · targeted for 15 November 2026

In 0.4.0-alpha1

  • Routing by message ID, the bundled Envelope and custom Packet types, and correlation IDs.
  • Pluggable framing through FrameCodec, with length-delimited framing by default; preambles with a deadline.
  • Transform middleware, connection setup and teardown hooks, and the before_send protocol hook on routed replies.
  • Transport fragmentation, protocol message assembly, and three-tier memory budgets.
  • A client with correlated calls, streamed replies, streaming sends, hooks, tracing, and pools.
  • The testkit feature and the wireframe_testing crate.

One routed request produces one reply, split across frames only by fragmentation, and a handler cannot return a stream.

Since 0.3.0

What to act on

The migration guide lists every change. The ones most likely to surprise are those that still compile.

  • A prepared application. WireframeServer::new calls its factory once per server run and shares the prepared application across connections. Per-connection state moves to on_connection_setup; WireframeServer::from_app takes an application already built, and spawn returns a ServerShutdown.
  • Preamble deadlines. The first read has a 10-second default deadline, with or without a preamble, and an error from the success handler now closes the connection.
  • Bounded, exact decoding. The bundled bincode decoders cap peer-declared lengths at 16 MiB for messages and 1 KiB for preambles, and trailing bytes after an envelope are a decoding error.
  • Binding totals and counted fragments. A declared total_body_len is a commitment, and fragment bytes count towards memory budgets.
  • Hooks on replies. before_send now runs on every handler response, including each fragment.
  • Pool limits. At most max_waiters acquisitions may queue, closed pools say so, and interrupted work discards its socket.
  • Reassembly caps. FragmentationConfig gains max_concurrent_partials and max_buffered_bytes, and Reassembler::new takes both.
  • Error enums. ClientError is now #[non_exhaustive], and it, ServerError, MessageAssemblyError, and ReassemblyError gain variants.
  • No linger. SocketOptions::linger and the builder’s linger are gone; close().await is the graceful path.
  • Deprecations. WireframeApp::handle_connection and handle_connection_result rebuild the middleware chains for every connection. Prepare the application once and use PreparedApp.
  • Dependencies. metrics-exporter-prometheus and tracing-subscriber are no longer brought along at run time. Declare them if the application uses them.

Tested, not yet wired

Ahead of the server

These parts ship and are tested on their own, but WireframeServer does not drive them, so adopting one means writing the glue. The users’ guide says how far each goes, and each has a tracking issue:

  • ConnectionActor, streaming and multi-packet responses (#874). Since the candidate, wired on main: the server runs an actor per connection, and route_response handlers can stream.
  • Push queues and SessionRegistry (#875)
  • Streaming request bodies (#876)
  • Extractors and app_data (#877). Since the candidate, removed on main by ADR 0017.
  • Recovery policies and the codec error metric (#878)
  • on_eof and the other protocol hooks (#879). Since the candidate, partly wired on main: on_command_end, handle_error, and stream_end_frame now run; on_eof does not.

On main at 7351347 · checked 18 November 2026 · not in a release

Since the candidate

The samples on this site run against the 0.4.0-alpha1 candidate at cd634074. The library’s main branch has moved on since, and these changes will reach a release only when one is cut from it:

  • Streaming handlers. WireframeApp::route_response takes a ResponseHandler that returns a Response, and every server connection now runs a ConnectionActor, so streamed and multi-packet replies reach the wire. on_command_end, handle_error, and stream_end_frame now run.
  • Extractors and app_data removed. ADR 0017 removes the unwired extractor and application-data APIs; shared state travels in the handler’s closure, as an Arc.
  • Shutdown reaches idle connections. stop() now ends a connection at its read boundary, so an idle peer no longer holds up drained.
  • A connection-local runtime. Teardown runs exactly once, including on panic and cancellation, and the active-connection gauge counts accepted sockets.

Proposed · none implemented at 7351347

Seven proposals

Seven requests for comments describe where the runtime could go next. Their documents have merged; their runtime has not, and the roadmap calls them “proposed work, not shipped guarantees”. Each link is the proposal at the checked revision.

  • RFC 0003, Native message adapter boundary. Keep the protocol’s identity: a typed boundary between native frames, application operations, and native replies, in place of mandatory envelope mapping.
  • RFC 0004, Duplex session driver. Give each direction room to move: a full-duplex lifecycle for reads, dispatch, unsolicited output, streams, and bounded termination.
  • RFC 0005, Negotiated transport entry points. Establish and transition connections, including negotiated upgrades and supplied streams, while keeping buffered bytes and transport ownership intact.
  • RFC 0006, Configurable framing primitives. Small, bounded framing primitives for native codecs, such as fixed-width lengths, short headers, and delimiters, without protocol state machines in core.
  • RFC 0007, Budgets, scheduling, and assembly. Capacity is part of the design: bound native frames, retained data, assembly, admitted work, and queued output across connections and streams.
  • RFC 0008, External adapter conformance harness. Show the working: test generic APIs and bounded protocol toys through public connectors and independent byte oracles. It is explicitly not certification.
  • RFC 0009, Datagram session transport. Expose packet boundaries and peer metadata to datagram adapters. Datagram boundaries and duplex progress are separate questions.

The first consumers proposed for these contracts are mxd serving Hotline, Modbus TCP, and a toy for the Agent Client Protocol. The toy is a prospective consumer test of bounded framing and duplex progress; it is not shipped, and the protocol’s own semantics stay outside wireframe.

Planned · upstream roadmap

Toward 1.0

  • Zero-copy payloads through the public byte APIs. This is not in the alpha: Serializer::serialize still returns Vec<u8>.
  • Alternative transports beyond raw TCP, a formal message versioning system, and built-in middleware or guides for TLS.
  • Formal verification of message assembly and dispatch: bounded model checks with Kani, model checks with Stateright, and proofs with Verus.

Track the detail in the upstream roadmap and the changelog.

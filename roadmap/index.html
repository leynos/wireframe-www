Released, next, and further out

0.3.0 is the release. 0.4.0 is in progress on the default branch and breaks things on purpose. Beyond that, the upstream roadmap is a plan, not a promise.

wireframe 0.3.0 · samples verified 2026-10-31

Released 6 April 2026

In 0.3.0

  • Routing by message ID, the bundled Envelope and custom Packet types, and correlation IDs.
  • Pluggable framing through FrameCodec, with length-delimited framing by default; preambles.
  • Transform middleware and connection setup and teardown hooks.
  • Transport fragmentation, protocol message assembly, and three-tier memory budgets.
  • Streaming responses, priority push queues, a fair connection actor, and a session registry, as building blocks.
  • A client with correlated calls, streamed replies, hooks, tracing, and pools.
  • The testkit feature and the wireframe_testing crate.

Unreleased · on the default branch

Coming in 0.4.0

The upstream changelog and the 0.3.0 to 0.4.0 migration guide list these, among others. They are breaking changes, so code written against 0.3.0 will need updates.

  • A prepared application. WireframeServer::new will call its factory once per server run and share the prepared application across connections, rather than building one per connection. Per-connection state moves to on_connection_setup; WireframeServer::from_app takes an application that is already built.
  • Non-exhaustive errors. ServerError and ClientError become #[non_exhaustive], and a saturated pool returns ClientError::PoolSaturated.
  • Bounded decoding. The bundled bincode decoders cap the container lengths a peer can declare, at 16 MiB for messages and 1 KiB for preambles.
  • No linger. SocketOptions::linger and the builder’s linger go; close().await is the graceful path.

Planned · upstream roadmap

Toward 1.0

  • Zero-copy payloads through the public byte APIs, replacing Vec<u8> where a frame can be shared.
  • Formal verification of message assembly and dispatch: bounded model checks with Kani, model checks with Stateright, and proofs with Verus.
  • Further client ergonomics, middleware, and streaming helpers.

Track the detail in the upstream roadmap and the changelog.

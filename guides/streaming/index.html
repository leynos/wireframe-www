What 0.3.0 wires up

Start with the boundary, because it decides what can be built today. In 0.3.0, a connection served by WireframeServer answers each routed request with exactly one reply frame. The types on this page, which are Response, PushQueues, ConnectionActor, and SessionRegistry, ship, are tested, and work together. The routed server path does not drive them.

In 0.3.0

Building blocks, not yet a server feature

Server-initiated pushes and multi-frame replies on a WireframeServer connection need a connection loop that runs the actor. That integration is upstream roadmap work. The client side is further along: call_streaming already reads a multi-frame reply from any server that sends one.

Responses that stream

Response describes a reply of any shape: Single frame, a Vec of frames, a Stream of fallible frames, a MultiPacket channel, or Empty. into_stream turns any of them into one boxed stream, which is the form the connection actor consumes.

Back-pressure through a channel

Response::with_channel returns a sender and a MultiPacket response around the matching receiver. A producer task sends frames whenever it has them. Each send waits while the channel is full, so a slow consumer slows the producer instead of growing a buffer. Dropping the last sender ends the response.

A protocol marks the end of such a stream with a terminator frame: the server side supplies it through the stream_end_frame protocol hook, and the client recognizes it through Packet::is_stream_terminator.

Priority push queues

PushQueues holds frames a connection should send without being asked: notifications, heartbeats, broadcast traffic. The builder sets a high- and a low-priority capacity, an optional rate limit, and an optional dead-letter queue. The rate limit defaults to 100 pushes a second, accepts up to 10,000, and is shared by both queues; unlimited() removes it.

The builder returns the queues and a cloneable PushHandle. Background tasks push through the handle: push_high_priority and push_low_priority wait for the rate limiter and then for room, while try_push drops the frame by policy instead of waiting, forwarding it to the dead-letter queue if one is configured.

The connection actor

ConnectionActor drains a connection’s push queues and its current response into one ordered output, polling a cancellation token so it stops promptly on shutdown. High-priority frames go first, but FairnessConfig lets a low-priority frame through after at most eight high-priority ones by default, optionally after a time slice as well, so a busy high queue cannot starve the low one.

In the sample the actor writes into a Vec; a connection loop would write each frame to its socket. The actor also runs the WireframeProtocol hooks installed with with_protocol, which is why those hooks have no effect on the routed path yet.

Find a connection later

SessionRegistry maps a ConnectionId to a connection’s PushHandle so that other tasks can reach it. It holds each handle weakly: when the connection’s queues are dropped, the entry no longer resolves, and stale entries are pruned on lookup or by prune().

SessionRegistry::default() requires the frame type to implement Default. Envelope does not, so in 0.3.0 a registry of envelope handles needs a frame type that does, or a wrapper.

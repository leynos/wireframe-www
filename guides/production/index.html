Bind and size the workers

WireframeServer is a typestate. new returns an unbound server; bind or bind_existing_listener returns a bound one, which can report local_addr and run. Configuration that belongs before binding, such as workers, backoff, readiness, and the preamble, is set on either.

  • Workers. One accept-loop task per worker, defaulting to the number of CPU cores and never fewer than one.
  • Applications. In 0.3.0 the factory is called once for every accepted connection, so per-connection state can live in the application. 0.4.0 changes this; see the roadmap.
  • Accept backoff. When accept fails, as it does when the process runs out of file descriptors, a worker waits and retries with exponential backoff between initial_delay and max_delay. Out-of-range values are corrected, not rejected.
  • Panics. A panic inside a connection task is caught, logged, and counted; the worker and every other connection carry on.

Readiness and shutdown

ready_signal takes a oneshot sender that fires once the workers are accepting, which is what a test or an orchestration probe should wait for. run serves until Ctrl+C; run_with_shutdown serves until the future it is given completes, then stops the workers. The sample stops the server through a oneshot channel and checks that it returns cleanly.

Timeouts and failure limits

SettingDefaultEffect in 0.3.0
buffer_capacity1,024 bytesFrames over the limit are a decoder error, and the connection closes
read_timeout_ms100 msA housekeeping interval: when it elapses with no frame, expired partial messages are purged and the connection keeps waiting
Deserialization failures10 in a rowThe connection closes; any good frame resets the count
preamble_timeoutNoneA preamble that does not arrive in time goes to the failure handler, and the connection closes
Memory budgets16, 64, 64 × frame limitReads slow at 80% of the aggregate cap and the connection closes past it; see memory budgets

In 0.3.0

An idle connection is never closed by the read timeout

Despite its name, read_timeout_ms does not disconnect a quiet peer. In 0.3.0 an idle connection stays open until the peer closes it or the server shuts down. Bound idle time at the protocol level, for example with a heartbeat the server expects, or in front of the server.

Metrics

With the default metrics feature, wireframe records through the metrics crate, so any recorder installed by the application receives them. With the feature off, the recording helpers become no-ops, so instrumentation can stay in place. The names are public constants:

NameKindRecords
wireframe_connections_activeGaugeOpen connections
wireframe_frames_processed_totalCounterFrames, labelled by direction
wireframe_errors_totalCounterErrors, labelled by kind
wireframe_connection_panics_totalCounterPanicking connection tasks
wireframe_codec_errors_totalCounterCodec errors, labelled by type and recovery policy

Logging goes through both log and tracing. Install a subscriber or logger to see the warnings for unrouted messages, rejected frames, and preamble errors.

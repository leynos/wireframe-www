Bind and size the workers

WireframeServer is a typestate. from_app takes a built application and new takes a factory, and both return an unbound server; bind or bind_existing_listener returns a bound one, which can report local_addr and run. Configuration that belongs before binding, such as workers, backoff, readiness, and the preamble, is set on either.

  • Workers. One accept-loop task per worker, defaulting to the available parallelism, which respects CPU quotas, and never fewer than one.
  • Applications. The factory runs once per server run, and the application is prepared before the server reports readiness. Every worker and connection shares that one immutable application, so per-connection state belongs in on_connection_setup.
  • Accept backoff. When accept fails, as it does when the process runs out of file descriptors, a worker waits and retries with exponential backoff between initial_delay and max_delay. Out-of-range values are corrected, not rejected.
  • Panics. A panic inside a connection task is caught, logged, and counted; the worker and every other connection carry on.

Readiness and shutdown

ready_signal takes a oneshot sender that fires once the workers are accepting, which is what a test or an orchestration probe should wait for. There are three ways to run and stop a server: run serves until Ctrl+C; run_with_shutdown serves until the future it is given completes, and dropping that future cancels the accept loops, so keep it alive for as long as the server should run; and spawn runs in the background and returns a cloneable ServerShutdown, whose stop requests shutdown and whose drained waits for it to finish. Dropping the last clone also requests shutdown.

Warning

Shutdown has no deadline

Shutdown waits for open connections, and it does not tell them to close. A single idle peer holds up run, run_with_shutdown, and drained until it disconnects. Bound the wait, or have the protocol close quiet connections:

In 0.4.0-alpha1

An idle connection is never closed by the read timeout

Despite its name, read_timeout_ms does not disconnect a quiet peer. A peer that never sends a first byte is cut off at the preamble deadline, but once it has, an idle connection stays open until it disconnects or the process exits, and shutdown will wait for it. Bound idle time at the protocol level, for example with a heartbeat the server expects, or in front of the server. There is no built-in TLS, so terminate that in front of the server too.

Metrics

With the default metrics feature, wireframe records through the metrics crate, so any recorder installed by the application receives them. With the feature off, the recording helpers become no-ops, so instrumentation can stay in place. An exporter such as metrics-exporter-prometheus is the application’s own dependency. The names are public constants:

Client pools add their own wireframe_pool_* metrics; wireframe_pool_connection_discards_total is the one to watch for socket churn. The users’ guide lists them.

Logging goes through both log and tracing. Install a subscriber or logger, from the application’s own dependencies, to see the warnings for unrouted messages, rejected frames, and preamble errors; wireframe installs nothing itself, so without one they are lost.

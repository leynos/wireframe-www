Build and connect

WireframeClient::builder() starts from the server’s defaults: a 4-byte big-endian length prefix, 1,024-byte frames, and the bincode serializer. The builder changes them before connecting. codec_config must agree with the server’s buffer_capacity: if small requests work and larger ones fail, the two limits disagree.

The builder also takes socket_options (TCP_NODELAY, keepalive, buffer sizes), a preamble to send on connect with with_preamble, and a preamble_timeout. close() shuts the connection down and runs the teardown hook.

Correlated calls

The client offers two levels. send, receive, and call work with any message type. The envelope-aware methods work with a Packet:

  • send_envelope stamps a correlation ID if the envelope has none, sends it, and returns the ID.
  • receive_envelope reads the next frame as an envelope.
  • call_correlated does both and fails with ClientError::CorrelationMismatch if the reply carries a different ID.

Correlation IDs come from a per-client counter, also available through next_correlation_id. A wireframe server copies the request’s ID onto its reply, so call_correlated against one always matches.

Read a streamed reply

call_streaming sends a request and returns a ResponseStream that yields each frame of the reply until the protocol’s terminator arrives. The envelope type decides what a terminator is, by overriding Packet::is_stream_terminator:

The stream checks every frame’s correlation ID and ends with ClientError::StreamCorrelationMismatch on the first that does not match. It borrows the client mutably, so no other request can go out until it is drained or dropped. StreamingResponseExt::typed_with maps frames to domain values and can skip control frames along the way.

The server in this sample is a few lines of plain Tokio, because a 0.3.0 WireframeServer answers each routed request with one frame. See what 0.3.0 wires up.

Hooks and tracing

  • Lifecycle. on_connection_setup returns per-connection state after the connection, and any preamble, succeeds; on_connection_teardown receives it on close(); on_error sees every failed send, receive, or call.
  • Per frame. before_send receives each serialized frame’s bytes before they are written, and after_receive each raw frame before it is decoded. Several may be registered; they run in order. The sample counts frames with before_send.
  • Tracing. The client emits tracing spans around every operation, at INFO for connect and close and DEBUG for data. tracing_config changes the levels and can time each operation.

Pools of warm sockets

With the pool feature, connect_pool keeps a bounded set of connected sockets. A lease forwards the usual request methods to one of them; the pool recycles sockets that sit idle past idle_timeout, and reruns the preamble and setup hook for each new one.

max_in_flight_per_socket is an admission budget, not parallel writes: I/O on one socket is still one request at a time. For a long-running workflow that should take fair turns with others, pool.handle() returns a PoolHandle that queues under the pool’s fairness policy instead of acquiring a lease each time.

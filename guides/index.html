Guides

Eight tasks, each built on code that compiles and runs against wireframe 0.3.0. Start with routing; the rest can be read in any order.

wireframe 0.3.0 · samples verified 2026-10-31

New to wireframe? Getting started builds a whole server and client first. The API reference on docs.rs is generated from the same release.

  • Routes, envelopes, and handlersA message ID picks the handler. The envelope carries everything else.
  • Frame codecs and preamblesFraming is a trait, not a fork. Describe the wire format once; the rest of the stack stays the same.
  • Middleware and lifecycle hooksHandlers observe; middleware answers. Hooks give each connection its own state.
  • Streaming, push, and sessionsThe parts for multi-frame replies and server-initiated traffic ship in 0.3.0. The routed connection path does not drive them yet.
  • Fragmentation and memory budgetsLarge messages cross the wire in pieces and are rejoined before a handler sees them, inside budgets the connection cannot exceed.
  • The client runtimeThe client uses the server’s codec, serializer, and envelope, so both ends of a protocol share one definition.
  • Testing at the frameNetworks deliver bytes in whatever pieces they like. Tests should too.
  • Running in productionThe server is a typestate, a pool of workers, and an accept loop that backs off when the listener fails.
